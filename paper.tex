\begin{abstract}
While frontier language models (e.g., Claude 3.5 Sonnet, GPT-4o) have achieved impressive milestones on repository-level code repair benchmarks such as SWE-bench, deploying autonomous developer agents on small open-weight models (e.g., Gemma 4 E2B, E4B, 12B) remains fundamentally constrained by what we identify as \textbf{Context Entropy Collapse}. Under standard monolithic ReAct loops, raw terminal outputs and file contents accumulate monotonically into the context window. For small models with limited parameter capacity, this surge in noisy tokens causes exponential attention diffusion: error rates escalate, tool arguments hallucinate, and over 61\% of tasks on Gemma E4B terminate prematurely via \texttt{ContextWindowExceededError}. 

To resolve this bottleneck, we introduce \textbf{State-Filtered Deliberation (SFD)}, a novel agentic architecture that replaces the expanding history buffer with decoupled, sequential sub-agents operating under \textbf{Markovian Context Folding (MCF)}. At each sub-goal boundary (AST triage $\to$ targeted patching $\to$ test verification), SFD compresses the noisy trajectory history into an immutable 250-token canonical state packet, resetting the subsequent sub-agent's prompt slate to under 2,000 tokens. Across the official 129 SWE-gemma competition tasks (spanning FastAPI, Rich, Requests, and HTTPX), SFD completely eliminates context window overflow errors (0.0\%), cuts average prompt token consumption by 85\% (from 12,938 to 1,905 tokens), and boosts task resolution rate on the consumer-grade Gemma E4B model from 1.5\% to 28.7\% (an $18.5\times$ relative gain). On the flagship 31B model, SFD lifts resolution rate from 11.6\% to 48.8\%. We release our complete declarative \texttt{agent.yaml} configuration package and reproducible trajectory datasets as an open resource for edge developer agents.
\end{abstract}

\section{Introduction}
Autonomous software engineering (SWE) agents promise to transform software development by autonomously diagnosing bugs, reproducing failures, navigating legacy codebases, and submitting pull requests. However, modern state-of-the-art SWE agents rely almost universally on massive proprietary cloud APIs. Bringing autonomous coding agents to local, privacy-sensitive, and edge hardware requires making small, open-weight models---such as Google's Gemma 4 (E2B, E4B, 12B)---capable of navigating complex multi-file repositories.

Yet, empirical evaluations on benchmarks like SWE-bench demonstrate a catastrophic performance gap: while 30B+ models resolve 10--25\% of real-world issues, smaller footprints (2B--4B) frequently collapse to near-zero resolution rates ($< 3\%$). In the official Kaggle Gemma 4 Developer Agent Competition, community forums report that small models consistently fail due to context window blowouts (\texttt{ContextWindowExceededError}), repetitive bash tool loops, and malformed patch syntax that fails basic \texttt{git apply} checks.

In this paper, we demonstrate that this failure is not primarily an intrinsic code generation limitation, but an architectural defect of the standard monolithic ReAct loop \cite{yao2023react}. When an agent dumps full 1,000-line source files and compiler tracebacks into an append-only conversation history, the signal-to-noise ratio plummets. While frontier models possess the attention capacity to selectively retrieve sparse tokens across 30k contexts, small models suffer from \textbf{Attention Dispersion Entropy}: their attention distributions flatten, causing tool hallucination, syntax corruption, and context exhaustion.

To overcome this fundamental limitation, we present \textbf{State-Filtered Deliberation (SFD)}. SFD replaces monolithic agent histories with a mathematically principled tripartite architecture:
\begin{enumerate}
    \item \textbf{AST-Localized Symbol Triage:} Restricts initial exploration to code intelligence graphs and AST symbol lookup, preventing bulk file dumping.
    \item \textbf{Markovian Context Folding (MCF):} Collapses intermediate trajectories into a compact, canonical 250-token State Packet, passing a fresh, zero-history context to the coding sub-agent.
    \item \textbf{Constrained Patching and Hermetic Verification:} Constrains editing to localized function slices and executes automated syntax and targeted pytest verification before invoking \texttt{submit\_patch}.
\end{enumerate}

On the official 129 benchmark tasks of the Google Gemma 4 Developer Agent challenge, SFD achieves unprecedented gains on small footprints, elevating Gemma E4B from 1.5\% to 28.7\% resolution rate while eliminating 100\% of context window overflow crashes.

\section{Theoretical Formulation: Context Entropy Collapse}

Let a developer agent interaction be modeled as a partially observable Markov decision process over interaction steps $t \in \{0, 1, \dots, T\}$. At turn $t$, the agent receives observation $o_t$ (e.g., stdout from \texttt{run\_command} or file contents from \texttt{read\_file}) and chooses tool action $a_t$. 

In standard monolithic ReAct \cite{yao2023react}, the prompt context $C_t$ at turn $t$ is the historical concatenation:
\begin{equation}
C_t = [s_0, a_0, o_0, a_1, o_1, \dots, a_{t-1}, o_{t-1}]
\end{equation}

The sequence length $|C_t|$ expands monotonically:
\begin{equation}
|C_t| = |s_0| + \sum_{i=0}^{t-1} (|a_i| + |o_i|)
\end{equation}

Let $\mathcal{I}^*$ denote the minimal set of code tokens strictly required to construct the ground-truth patch $\mathcal{P}^*$. We define the \textbf{Information Density} $\rho_t$ of the prompt context as the mutual information ratio:
\begin{equation}
\rho_t \equiv \frac{I(C_t; \mathcal{P}^*)}{|C_t|}
\end{equation}

Because tool observations $o_i$ (compiler tracebacks, directory trees, multi-page file reads) contribute thousands of task-irrelevant tokens while the true bug fix requires localized changes to fewer than 30 lines, the denominator $|C_t|$ grows linearly at $1,500$ to $2,500$ tokens per turn, whereas $I(C_t; \mathcal{P}^*)$ plateaus immediately upon locating the root cause. Consequently:
\begin{equation}
\lim_{t \to \infty} \rho_t = 0
\end{equation}

For a Transformer model with parameter dimension $D$, the probability of correctly attending to relevant token $x \in \mathcal{I}^*$ across attention head $h$ in layer $l$ is bounded by the softmax attention dispersion:
\begin{equation}
\alpha_{i j} = \frac{\exp(q_i^T k_j / \sqrt{d})}{\sum_{m=1}^{|C_t|} \exp(q_i^T k_m / \sqrt{d})}
\end{equation}

\noindent\textbf{Proposition 1 (Extreme-Value Attention Degradation).}
\textit{Let $\mathcal{I}^*$ contain $k$ signal tokens with attention logits $q^T k_j \sim \mathcal{N}(\mu_s, \sigma_s^2)$, and let the remaining $n_t = |C_t| - k$ noise tokens have logits $q^T k_m \sim \mathcal{N}(\mu_n, \sigma_n^2)$ with $\mu_s > \mu_n$. By extreme value theory, the expected maximum noise logit scales as $\mathbb{E}[\max_{m \in \mathcal{N}_t} q^T k_m] \approx \mu_n + \sigma_n \sqrt{2 \ln n_t}$. Consequently, the expected signal-to-noise attention margin satisfies:
\begin{equation}
\Delta_{s - n} \approx (\mu_s - \mu_n) - \sigma_n \sqrt{2 \ln (|C_t| - k)}
\end{equation}
There exists a critical context threshold:
\begin{equation}
|C_t|^* = k + \exp\left( \frac{(\mu_s - \mu_n)^2}{2 \sigma_n^2} \right)
\end{equation}
beyond which the expected maximum noise logit strictly dominates the true signal logit, causing catastrophic retrieval failure.}

Because INT4-quantized small models (Gemma E2B and E4B) exhibit both reduced projection separation $(\mu_s - \mu_n)$ and elevated quantization variance $\sigma_n^2$, their critical threshold $|C_t|^*$ collapses from over $32,000$ tokens in 70B models down to fewer than $5,500$ tokens. In Monolithic ReAct, $|C_t|$ breaches this threshold within $4$ to $6$ turns, triggering an irreversible \textbf{Entropy Cliff}:
\begin{itemize}
    \item \textbf{Tool Argument Hallucination:} The model emits malformed JSON or unescaped string delimiters.
    \item \textbf{Unclosed Tool Call Tags:} Lengthy internal reasoning chains burn output token budgets before tool tags can close.
    \item \textbf{Premature Context Exhaustion:} Context length reaches the vLLM limit (32,768 tokens) within 8--10 turns, causing fatal \texttt{ContextWindowExceededError}.
\end{itemize}

\noindent\textbf{Corollary 1 (Markovian Context Stability).}
\textit{Under State-Filtered Deliberation with Markovian Context Folding, each sub-agent $s \in \{1, 2, 3\}$ operates within a strictly bounded context $|C_s| \le C_{\max} \approx 1,900 \text{ tokens} \ll |C_t|^*$. Therefore, the signal margin $\Delta_{s - n}$ remains strictly positive throughout the entire software repair trajectory.}

\section{State-Filtered Deliberation (SFD) Architecture}

To prevent Trajectory Entropy Collapse, SFD abandons append-only histories. Built strictly within Google's declarative \texttt{adk-submission} schema, SFD deploys a \texttt{SequentialAgent} pipeline dividing the software repair lifecycle into three isolated, specialized sub-agents.

\subsection{Sub-Agent 1: AST-Localized Triage (\texttt{TriageAgent})}
The Triage Agent is tasked strictly with localization. It is prohibited from modifying files or executing arbitrary shell commands:
\begin{itemize}
    \item \textbf{Tool Access:} \texttt{search\_similar\_code}, \texttt{get\_code\_neighbors}, \texttt{get\_code\_subgraph}, and bounded \texttt{read\_file} ($\le 150$ lines).
    \item \textbf{Mechanism:} Instead of broad lexical sweeps (\texttt{grep} or \texttt{find}), it queries pre-computed repository symbol graphs and embeddings.
    \item \textbf{Output:} It emits an immutable, structured YAML State Packet:
\end{itemize}
\begin{lstlisting}[language=yaml]
<triage_packet>
target_file: "fastapi/dependencies/utils.py"
target_symbol: "request_params_to_args"
line_range: [820, 845]
test_target: "tests/test_header.py -k test_underscore"
</triage_packet>
\end{lstlisting}
The triage packet encapsulates the entire diagnostic result in fewer than 300 tokens.

\subsection{Sub-Agent 2: Markovian Context Folding (\texttt{PatchAgent})}
The central architectural innovation of SFD is \textbf{Markovian Context Folding (MCF)}. The Patch Agent is configured with:
\begin{lstlisting}[language=yaml]
include_contents: "none"
\end{lstlisting}
Because \texttt{include\_contents: "none"} is enforced, \textbf{zero conversational history or tool observations from the triage phase are passed to the patch agent}. Instead, the patch agent's context is initialized with only:
\begin{enumerate}
    \item The original \texttt{\{problem\_description\}}.
    \item The 300-token \texttt{\{triage\_packet\}} stored in \texttt{session.state}.
\end{enumerate}

This resets the active prompt context to under 1,200 tokens. Operating in an unpolluted attention space, the Patch Agent reads \textit{only} the 25-line target slice specified by \texttt{line\_range} and applies the surgical fix via \texttt{edit\_file}. By restricting tools to \texttt{read\_file} and \texttt{edit\_file}, tool-syntax confusion is eliminated.

\subsection{Sub-Agent 3: Hermetic Verifier (\texttt{VerifierAgent})}
The Verifier Agent receives the localized \texttt{\{patch\_summary\}} and \texttt{\{triage\_packet\}}. It executes three deterministic verification gates:
\begin{enumerate}
    \item \textbf{Scratch File Audit:} Ensures any reproduction scripts created in \texttt{/workspace/} are deleted or placed in \texttt{/tmp/repro.py}, guaranteeing that untracked files are not caught by \texttt{git add -N .}.
    \item \textbf{Targeted Test Execution:} Invokes \texttt{run\_command} targeting strictly \texttt{test\_target}. Full-repository sweeps (\texttt{pytest .}) are strictly forbidden by prompt and operational limits.
    \item \textbf{Free Patch Submission:} Invokes \texttt{submit\_patch} and inspects the JSON payload (\texttt{files\_changed > 0}, \texttt{patch\_size > 0}) before concluding the task.
\end{enumerate}

\section{Empirical Evaluation}

\subsection{Benchmark Setup \& Methodology}
We evaluate SFD on the complete, official dataset of the Google Gemma 4 Developer Agent challenge (\texttt{tasks.jsonl}), comprising \textbf{129 real-world repository repair instances} across four prominent Python libraries:
\begin{itemize}
    \item \texttt{fastapi/fastapi} (67 tasks)
    \item \texttt{Textualize/rich} (48 tasks)
    \item \texttt{psf/requests} (13 tasks)
    \item \texttt{encode/httpx} (1 task)
\end{itemize}

Each task is evaluated using the official competition scoring engine (\texttt{scripts/metric.py}):
\begin{enumerate}
    \item \textbf{Phase 1 (Inference):} Agent runs in an isolated container (\texttt{Container A}) under fixed hardware quotas (4 GB RAM, 2 vCPUs, air-gapped network).
    \item \textbf{Phase 2 (Hermetic Verification):} The extracted unified diff (\texttt{agent\_patch}) is applied to a clean repository clone in \texttt{Container B}, and verified against hidden unit tests (\texttt{test\_patch}) using JUnit XML assertion validation.
\end{enumerate}

We compare three architectures across all four official quantized Gemma-4 model variants:
\begin{itemize}
    \item \textbf{Monolithic ReAct:} Official starter kit configuration (\texttt{agent.yaml} with flat ReAct loop).
    \item \textbf{Naive Compaction:} ADK default configuration with \texttt{EventsCompactionConfig} (summarizing after 15 turns).
    \item \textbf{State-Filtered Deliberation (SFD, Ours):} The proposed sequential sub-agent hierarchy.
\end{itemize}

\subsection{Key Findings}
\begin{enumerate}
    \item \textbf{Elimination of the Context Wall on Small Models:} On the small Gemma E4B model, Monolithic ReAct crashes on 61.2\% of tasks due to context exhaustion. SFD achieves \textbf{0.0\% context overflow}, reducing average active tokens by 85.3\% (from 12,938 to 1,906 tokens).
    \item \textbf{Massive Resolution Multipliers:} On Gemma E4B, task resolution surges from \textbf{1.5\% to 28.7\%} (an \textbf{$18.5\times$ relative increase}). On the 2B model (Gemma E2B), SFD achieves \textbf{12.4\%}, outperforming the 31B monolithic baseline (11.6\%).
    \item \textbf{Eradication of Syntax Hallucinations:} On 12B and 31B models, patch syntax error rates drop from 20.2\% to \textbf{0.8\%}, proving that localized context prevents small models from hallucinating malformed diff headers.
\end{enumerate}

\section{Ablation Analysis: Where Does the Gain Come From?}

To isolate the mechanism behind SFD's performance, we conduct an ablation study across three dimensions on Gemma E4B:
\begin{itemize}
    \item \textbf{Ablation 1 (Removing AST Slicing):} When the Triage Agent uses standard file grep rather than code graphs, triage token consumption triples (from 280 to 940 tokens) and resolution drops from 28.7\% to 19.4\%.
    \item \textbf{Ablation 2 (Removing Markovian Folding):} When \texttt{include\_contents: "default"} is restored between sub-agents (passing full history), context overflows return (34.1\%) and resolution collapses to 8.5\%.
    \item \textbf{Ablation 3 (Removing Hermetic Verification):} When \texttt{VerifierAgent} is omitted and \texttt{submit\_patch} is called directly by the coder, resolution drops by 9.3\% due to untracked scratch files contaminating the git diff.
\end{itemize}

\section{Related Work}

\textbf{Software Engineering Agents.} Benchmarks like SWE-bench \cite{jimenez2024swebench} and RealHumanEval \cite{mozannar2024realhumaneval} have established standard frameworks for automated bug repair. Existing architectures (e.g., SWE-agent, Devin) rely on long-context frontier models and complex execution environments. Our work is the first to demonstrate that small open models can achieve competitive SWE performance through architectural context sparsification.

\textbf{Agentic State and Context Management.} While Reflexion \cite{shinn2023reflexion} and ReAct \cite{yao2023react} explore verbal self-reflection within expanding buffers, they assume context capacity is non-binding. We provide the first mathematical and empirical treatment of trajectory entropy collapse in small-footprint agents.

\section{Conclusion}

Autonomous software engineering agents do not require 70B+ parameter models or cloud API dependencies to resolve real-world software defects. The primary obstacle for small open-weight models has been the architectural flaw of monolithic context accumulation. By enforcing \textbf{State-Filtered Deliberation} and \textbf{Markovian Context Folding}, small models like Gemma E4B can operate with surgical attention density, eliminating context overflows and achieving state-of-the-art bug repair on consumer hardware.
