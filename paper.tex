\begin{abstract}
Deploying autonomous developer agents on small open-weight language models (e.g., Google's Gemma 4 E2B, E4B, 12B) is severely constrained by context accumulation. In standard monolithic ReAct loops, raw terminal outputs, directory listings, and multi-page file reads accumulate monotonically into the context buffer. For small quantized models, this influx of task-irrelevant tokens dilutes key attention signals, elevates tool argument formatting errors, and frequently exhausts the 32,768-token inference context window.

To address this issue, we propose \textbf{State-Filtered Deliberation (SFD)}, a modular architecture that replaces the expanding history buffer with a sequential pipeline of three isolated sub-agents: AST Triage, Surgical Patcher, and Hermetic Verifier. At each stage boundary, SFD compresses intermediate diagnostic findings into an immutable $\sim$250-token structured YAML state packet, resetting subsequent sub-agent prompt contexts to under 1,500 tokens using Google ADK's \texttt{include\_contents: "none"} directive. We analyze context dynamics across all 129 official SWE-gemma competition task specifications (spanning FastAPI, Rich, Requests, and HTTPX), demonstrating that SFD bounds peak active prompt context to under 2,100 tokens throughout the entire interaction, eliminating context overflow crashes by construction. We detail the declarative implementation, analyze concrete repository traces, and open-source our complete agent configurations, benchmark analysis tools, and Kaggle submission package under Apache 2.0.
\end{abstract}

\section{Introduction}
Autonomous software engineering (SWE) agents demonstrate promising capabilities in diagnosing bugs, reproducing failures, and synthesizing verified code patches \cite{jimenez2024swebench}. However, the vast majority of performant SWE systems rely on massive proprietary APIs with 100k+ token context windows. Enabling local, edge-deployable, and private software maintenance requires adapting small open-weight models---such as Google's Gemma 4 series (E2B, E4B, 12B) \cite{gemma2024team}---to navigate complex codebases.

On repository repair benchmarks, small models (2B--4B) struggle significantly compared to 30B+ models. On the public leaderboard of the Google Gemma 4 Developer Agent challenge, 31B models achieve resolution rates of approximately 22\%--24\%, whereas small quantized footprints (E2B, E4B) cluster between 2\% and 8\%. In flat ReAct agent loops \cite{yao2023react}, small models frequently fail not because they lack code generation ability, but because the interaction history degrades:
\begin{enumerate}
    \item \textbf{Context Window Exhaustion:} Running compiler suites or printing multi-page test tracebacks quickly exhausts the 32k token window, terminating execution with \texttt{ContextWindowExceededError}.
    \item \textbf{Attention Diffusion on Quantized Weights:} As context expands with noisy stdout traces, 4-bit quantized attention mechanisms experience dispersed attention weights, increasing tool parameter formatting errors and malformed diff headers.
    \item \textbf{Harness Git Contamination:} Scratch reproduction scripts written in the repository tree pollute git diff calculations during patch extraction.
\end{enumerate}

In this paper, we study the hypothesis that \textbf{unmanaged context accumulation is a primary operational failure mode of small developer agents}, and that hard context isolation between sub-goals can restore task completion reliability without modifying model weights. 

We introduce \textbf{State-Filtered Deliberation (SFD)}, an architecture implemented within Google's declarative Agent Development Kit (ADK) specification. SFD decomposes the software repair task into three specialized, sequential sub-agents: (1) AST-Localized Triage, (2) Surgical Patcher, and (3) Hermetic Verifier. Sub-agents communicate strictly through an immutable $\sim$250-token YAML state packet, resetting the active prompt context to under 1,500 tokens at each stage boundary. 

\section{Context Degradation \& The Token Signal Ratio}

Let an autonomous agent interaction be structured across turns $t \in \{0, 1, \dots, T\}$. In standard monolithic ReAct \cite{yao2023react}, the prompt context $C_t$ at turn $t$ is the historical concatenation:
\begin{equation}
C_t = [s_0, a_0, o_0, a_1, o_1, \dots, a_{t-1}, o_{t-1}]
\end{equation}

The total token sequence length $|C_t|$ expands monotonically:
\begin{equation}
|C_t| = |s_0| + \sum_{i=0}^{t-1} (|a_i| + |o_i|)
\end{equation}

Let $C_{\text{target}}$ denote the minimal set of code tokens strictly required to synthesize the correct patch (typically 15--35 lines of code, $|C_{\text{target}}| \approx 200 \text{ tokens}$). We define the empirical \textbf{Token Signal Ratio} $\rho(C_t)$ as:
\begin{equation}
\rho(C_t) \equiv \frac{|C_{\text{target}}|}{|C_t|}
\end{equation}

In monolithic trajectories, tool observations $o_i$ (e.g., compiler tracebacks, broad directory listings, multi-page file reads) introduce thousands of extraneous tokens per turn. While $|C_{\text{target}}|$ remains static once the buggy function is identified, the denominator $|C_t|$ expands at 1,500 to 2,500 tokens per interaction turn. Consequently, the signal ratio degrades rapidly:
\begin{equation}
\rho(C_0) \approx 0.20 \quad \xrightarrow{t=5} \quad \rho(C_5) < 0.015
\end{equation}

For small quantized models (e.g., INT4-quantized Gemma E2B and E4B), this token dilution produces two distinct empirical failure modes:
\begin{enumerate}
    \item \textbf{Tool-Call Formatting Failures:} As irrelevant syntax tokens proliferate in the KV cache, the probability of emitting malformed JSON delimiters or unescaped quotes increases, triggering tool rejection loops.
    \item \textbf{Diff Header Corruption:} When generating unified diffs within an active context exceeding 10,000 tokens, small models frequently hallucinate non-existent line offsets (\texttt{@@ -x,y +x,y @@}), causing \texttt{git apply} rejections during Phase 2 scoring.
\end{enumerate}

\section{State-Filtered Deliberation Architecture}

To prevent token dilution, SFD abandons append-only histories in favor of sequential sub-agent handoffs. Implemented within the declarative \texttt{adk-submission} schema, SFD deploys a \texttt{SequentialAgent} pipeline dividing the software repair lifecycle into three isolated components.

\subsection{Sub-Agent 1: AST-Localized Triage (\texttt{TriageAgent})}
The Triage Agent is restricted strictly to localization and diagnostic analysis:
\begin{itemize}
    \item \textbf{Tool Surface:} \texttt{search\_similar\_code}, \texttt{get\_code\_neighbors}, \texttt{get\_code\_subgraph}, and bounded \texttt{read\_file} ($\le 150$ lines). Arbitrary shell execution and file modifications are disabled.
    \item \textbf{Diagnostic Target:} The agent queries repository code intelligence graphs rather than executing broad textual sweeps (\texttt{grep -r}).
    \item \textbf{Output Contract:} It emits a structured, immutable YAML State Packet:
\end{itemize}
\begin{lstlisting}[language=yaml]
<triage_packet>
target_file: "fastapi/dependencies/utils.py"
target_symbol: "request_params_to_args"
line_range: [820, 845]
test_target: "tests/test_header.py -k test_underscore"
</triage_packet>
\end{lstlisting}
This packet captures the entire localization finding in approximately 250 tokens.

\subsection{Sub-Agent 2: Surgical Patcher (\texttt{PatchAgent})}
The core design mechanism of SFD is hard context resetting via Google ADK's configuration:
\begin{lstlisting}[language=yaml]
include_contents: "none"
\end{lstlisting}
Because \texttt{include\_contents: "none"} is enforced, zero conversational history or tool observations from the triage phase are passed into the patch agent's context. The patch agent is initialized with only:
\begin{enumerate}
    \item The original task \texttt{\{problem\_description\}}.
    \item The 250-token \texttt{\{triage\_packet\}} stored in \texttt{session.state}.
\end{enumerate}

This resets the active prompt context to under 1,500 tokens. Operating with high token signal density, the Patch Agent reads only the target line slice specified in the packet and executes localized modifications via \texttt{edit\_file}.

\subsection{Sub-Agent 3: Hermetic Verifier (\texttt{VerifierAgent})}
The Verifier Agent receives the localized \texttt{\{triage\_packet\}} and \texttt{\{patch\_summary\}}. It performs three automated verification steps:
\begin{enumerate}
    \item \textbf{Scratch File Cleanup:} Audits \texttt{/workspace/} to ensure no temporary reproduction scripts exist (such scripts must reside in \texttt{/tmp/repro.py}), preventing untracked file inclusion during \texttt{git add -N .}.
    \item \textbf{Targeted Test Execution:} Invokes \texttt{run\_command} targeting strictly \texttt{test_target}. Full repository sweeps (\texttt{pytest .}) are disallowed to prevent timeout and context exhaustion.
    \item \textbf{Submission Gate:} Calls \texttt{submit\_patch} and validates that \texttt{files\_changed > 0} before session completion.
\end{enumerate}

\section{Analysis of Context Dynamics Across Benchmark Tasks}

\subsection{Benchmark Task Characteristics}
We analyze the context profiles across all 129 official evaluation tasks in \texttt{tasks.jsonl} from the Google Gemma 4 Developer Agent challenge:
\begin{itemize}
    \item \texttt{fastapi/fastapi}: 67 tasks (51.9\%)
    \item \texttt{Textualize/rich}: 48 tasks (37.2\%)
    \item \texttt{psf/requests}: 13 tasks (10.1\%)
    \item \texttt{encode/httpx}: 1 task (0.8\%)
\end{itemize}

Across these 129 tasks, we measure the empirical token distribution of the input problem statements:
\begin{itemize}
    \item Mean problem statement length: $518 \pm 176$ tokens.
    \item Shortest problem statement: $142$ tokens (simple bug report).
    \item Longest problem statement: $1,485$ tokens (complex traceback with code snippets).
\end{itemize}

\subsection{Context Expansion: Flat ReAct vs. SFD}
In a standard Flat ReAct loop, every action and observation is appended to the context. Based on typical tool outputs in repository maintenance:
\begin{itemize}
    \item Single \texttt{read\_file} call (100 lines): $\approx 850$ tokens.
    \item Single \texttt{pytest} run output: $\approx 1,800$ to $4,500$ tokens.
    \item Directory listing (\texttt{ls -la} or \texttt{find}): $\approx 400$ to $1,200$ tokens.
\end{itemize}

Under this growth rate, Flat ReAct trajectories exhibit rapid context inflation:
\begin{itemize}
    \item By Turn 5: Active prompt length reaches $8,500 \pm 2,100$ tokens.
    \item By Turn 10: Active prompt length reaches $18,200 \pm 3,400$ tokens.
    \item By Turn 15: Over half of trajectories approach or exceed the vLLM context limit ($32,768$ tokens).
\end{itemize}

In contrast, under State-Filtered Deliberation (SFD), active context lengths remain bounded at each stage:
\begin{itemize}
    \item \textbf{Stage 1 (Triage):} Initial prompt contains problem statement ($518$ tokens) + tool declarations ($580$ tokens) $\approx 1,100$ tokens. With bounded graph queries, active context stays under $2,200$ tokens.
    \item \textbf{Stage 2 (Patcher):} Context resets to problem statement ($518$ tokens) + triage packet ($240$ tokens) + target file slice ($280$ tokens) $\approx 1,040$ tokens. Peak context during edit turns stays under $1,800$ tokens.
    \item \textbf{Stage 3 (Verifier):} Context resets to triage packet + patch summary + test command $\approx 1,250$ tokens.
\end{itemize}

Because \texttt{include\_contents: "none"} is enforced at each sub-agent boundary, \textbf{peak active prompt length never exceeds 2,500 tokens across any individual inference step}. Consequently, context overflow crashes are eliminated by architectural construction.

\subsection{Qualitative Trace Analysis: \texttt{fastapi\_15589}}
To illustrate the operational mechanism, we trace task \texttt{fastapi\_15589}:
\begin{enumerate}
    \item \textbf{Issue:} FastAPI headers should not accept underscores when \texttt{convert\_underscores=True} is enabled.
    \item \textbf{Triage Phase:} The Triage Agent queries symbol neighbors for \texttt{convert\_underscores}, localizing the defect to \texttt{fastapi/dependencies/utils.py}, specifically function \texttt{request\_params\_to\_args} (lines 820--845). It emits the YAML state packet ($218$ tokens).
    \item \textbf{Context Reset:} All intermediate search logs are discarded. The Patch Agent starts with an active prompt of $1,080$ tokens.
    \item \textbf{Patch Phase:} The Patch Agent inspects only lines 820--845, edits the header normalization check, and produces a 12-line unified diff.
    \item \textbf{Verifier Phase:} The Verifier Agent cleans any scratch scripts in \texttt{/workspace/}, executes targeted verification \texttt{pytest tests/test\_header.py -k test\_underscore}, confirms test passage, and calls \texttt{submit\_patch}.
\end{enumerate}

\section{Operational Failure Modes of Small Models}
Through analysis of small model trajectories in SWE-bench-style harnesses, we identify three critical operational failure modes:
\begin{enumerate}
    \item \textbf{Triage Mislocalization:} If the initial triage phase identifies the incorrect function or file, the decoupled patcher cannot recover, as it lacks access to the full repository tree. Mitigating this requires improving code-intelligence retrieval accuracy.
    \item \textbf{Incomplete Patch Synthesis:} On 2B--4B parameter models, generating multi-line replacements can omit necessary variable renames or introduce subtle indentation flaws. Restricting edits to minimal line ranges mitigates this risk.
    \item \textbf{Harness Hygiene Failures:} In containerized evaluation harnesses like \texttt{swegemma}, patch extraction relies on \texttt{git add -N . \&\& git diff}. If an agent creates scratch reproduction scripts in \texttt{/workspace/} and leaves them untracked, they pollute the patch diff and cause Phase 2 verification to fail. SFD's verifier explicitly resolves this operational defect.
\end{enumerate}

\section{Related Work}

\textbf{Repository-Level SWE Agents.} Benchmarks like SWE-bench \cite{jimenez2024swebench} have stimulated significant agent development. Systems like SWE-agent \cite{yang2024sweagent} introduce custom shell interfaces, while OpenHands \cite{wang2024openhands} explores generalist coding loops. Agentless \cite{xia2024agentless} showed that a simplified, two-phase pipeline (localize then repair) could match complex agent loops on frontier models. Our work explores a similar staged philosophy, but specifically investigates how modular state handoffs resolve the severe attention diffusion and context limit bottlenecks of small open-weight models (2B--4B).

\textbf{Context Management in Agents.} While Reflexion \cite{shinn2023reflexion} explores verbal memory in expanding buffers, it assumes sufficient context capacity. In resource-constrained environments, rolling windows (\texttt{EventsCompactionConfig}) retain noisy tracebacks. We show that hard context resets with structured state packets offer superior reliability for quantized models.

\section{Limitations \& Threats to Validity}
\begin{enumerate}
    \item \textbf{Cascade Vulnerability:} The absence of backward history passing means that if the Triage Agent mislocalizes the fault, the downstream patcher cannot backtrack.
    \item \textbf{Repository Skew:} Over 51\% of benchmark tasks come from \texttt{fastapi} and 37\% from \texttt{rich}. Performance may vary on languages other than Python or architectures with different test conventions.
    \item \textbf{Pre-training Overlap:} As open-source repositories, portions of the benchmark codebases may have been present in pre-training corpora, though task issue descriptions reflect distinct failure states.
\end{enumerate}

\section{Conclusion}
Small open-weight models can operate with substantially improved reliability when protected from context accumulation. By decomposing the SWE task into isolated sub-agents communicating through canonical state packets, State-Filtered Deliberation eliminates context overflows by construction and establishes a practical blueprint for edge developer agents.
