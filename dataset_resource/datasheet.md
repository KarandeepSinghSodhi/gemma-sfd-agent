# Datasheet for Dataset: ATIF-Gemma

Following the *Datasheets for Datasets* standard (Gebru et al., 2021).

---

## 1. Motivation

- **For what purpose was the dataset created?**  
  Current software engineering (SWE) agent benchmarks report scalar pass/fail resolution rates, obscuring the multi-turn dynamics of agent failure. For small, quantized open-weight models (e.g. `gemma-4-e4b-it-qat-w4a16-ct`), understanding why agents plateau at low resolution rates (median 5.0% across 197 teams on the official Small Model Prize leaderboard) was hindered by limited publicly available trace data linking compact-agent execution trajectories to test outcomes and failure diagnoses. ATIF-Gemma was created to provide an open, standardized empirical diagnostic corpus and failure taxonomy.

- **Who created the dataset and on behalf of which entity?**  
  Karandeep Singh Sodhi, as an open scientific resource submission for the Kaggle Gemma 4 Developer Agent Competition (Paper Track: Best New Resource).

- **Who funded the creation of the dataset?**  
  Compute was provided by Kaggle and Google via NVIDIA L4 GPU quota allocations during the competition.

---

## 2. Composition

- **What do the instances that comprise the dataset represent?**  
  Each instance represents a complete, multi-turn execution trace of an autonomous software engineering agent attempting to resolve a real-world SWE-bench bug inside a sandboxed Python repository.

- **How many instances are there in total?**  
  112 full-fidelity ATIF v1.7 execution traces, comprising 1,518 LLM turns, 1,328 tool invocations, and 11,706,178 logged tokens across 32 unique SWE-bench tasks.

- **What data does each instance contain?**  
  - *Metadata*: Task ID, target repository, base git commit, agent architecture, model version, sampling hyperparameters (`temperature=0.0`, `seed=42`), and hardware environment.
  - *Interaction Turns*: Sequential history of system prompts, agent thoughts within the reasoning budget, tool calls with structured JSON arguments, raw stdout/stderr observations, and exact token consumption (`prompt_tokens`, `completion_tokens`).
  - *Evaluation Outcomes*: Agent synthesized unified diff, git patch apply status, and Phase 2 held-out pytest exit codes.

- **Are there any subsets or splits?**  
  Yes, 5 experimental partitions across 32 unique tasks:
  1. `Cohort 1 (Canonical Paired)`: 24 traces (8 tasks x 3 configs)
  2. `Cohort 2 (Stratified Random)`: 24 traces (8 tasks x 3 configs)
  3. `Cohort 1 Rerun (Reproducibility)`: 16 traces (8 tasks x 2 configs rerun under identical greedy settings)
  4. `Cohort 3 (Stratified Disjoint)`: 24 traces (8 tasks x 3 configs)
  5. `Cohort 4 (Stratified Disjoint)`: 24 traces (8 tasks x 3 configs)
  
  Additionally, a boolean flag `env_suspected` in `corpus_metadata.csv` identifies 20 runs where Phase 2 test collection crashed due to offline sandbox environment defects (virtual environment path shadowing or missing wheelhouse packages such as `inline_snapshot`). Resolution is 6/96 (6.25%) across all primary runs, and 6/80 (7.50%) across valid-environment primary runs.

- **Does the dataset contain sensitive or personally identifiable data?**  
  No. All code and test suites originate from open-source GitHub repositories under permissive licenses (`fastapi`, `rich`, `requests`, `httpx`). ATIF traces record the model's interaction history without disclosing confidential held-out competition test harnesses.

---

## 3. Collection Process

- **How was the data acquired?**  
  Traces were generated by deploying three controlled agent architectures (`flat_starter`, `flat_controlled`, `sfd`) built with Google's Agent Development Kit (ADK 1.36.1) on Kaggle's 4x NVIDIA L4 GPU cluster (`NvidiaL4`, 96 GB aggregate VRAM).

- **What software and models were used?**  
  - Model: `gemma-4-e4b-it-qat-w4a16-ct` (4-bit quantized Gemma 4 E4B).
  - Inference Server: vLLM 0.19.1 with tensor-parallel size 4 (`tp=4`).
  - Agent Harness: Google ADK and `swegemma`.
  - Sampling: Greedy decoding (`temperature=0.0`, `seed=42`, `max_output_tokens=8192`, `thinking_budget=1536`).

- **Were ground-truth patches and tests validated?**  
  Yes. Every instance cross-references author reference patches and held-out test patches from SWE-bench (Jimenez et al., 2024).

---

## 4. Preprocessing and Cleaning

- **What preprocessing was performed?**  
  Traces were validated against the Agent Trajectory Interchange Format (ATIF v1.7) JSON schema, conforming to the Harbor ATIF v1.7 specification (Harbor Framework Contributors, 2026). All timestamps, durations, exit codes, and token metrics were extracted and compiled into `corpus_metadata.csv` with zero hand-typed values.

---

## 5. Uses

- **What are the intended uses of the dataset?**  
  - Benchmarking agentic workflows on small open-weight language models.
  - Investigating failure mechanisms (syntax corruption, context bloat, sub-agent bypassing).
  - Evaluating context management strategies (e.g. stage-boundary observation masking).
  - Developing automated post-hoc error diagnostic and repair toolkits.

- **What should the dataset NOT be used for?**  
  Evaluating closed frontier models (e.g. Claude 3.5 Sonnet, GPT-4o) without noting that the traces reflect 4-bit quantized Gemma 4 E4B behavior.
